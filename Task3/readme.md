## Анализ проблем и рисков текущей архитектуры
### Текущие проблемы:
1. **Синхронные вызовы создают "узкое" место** - `ins-product-aggregator` должен синхронно опрашивать все страховые компании, что приводит к длительным ответам
2. **Хрупкие зависимости** - Ошибки в одной страховой компании влияют на доступность всего сервиса
3. **Несвоевременное обновление данных** - 15-минутные интервалы обновления не обеспечивают актуальность данных
4. **Проблемы масштабирования** - Добавление 5 новых страховых компаний усугубит существующие проблемы

### Риски при росте нагрузки:
1. **Увеличение времени ответа** пропорционально количеству страховых компаний
2. **Каскадные сбои** при проблемах у любого из партнеров
3. **Нарушение SLA** для B2B-клиентов из-за нестабильности
4. **Потеря данных** при сбоях во время синхронных вызовов

## Предлагаемые решения
### 1. Переход на Event-Driven архитектуру
Внедряем Kafka как брокер сообщений.
* Создаем топики:
    * `insurance-products-updates` - для обновлений продуктов
    * `policy-creations` - для событий оформления страховок

### 2. Изменения во взаимодействиях сервисов
Сервис `ins-product-aggregator`:
* Периодически опрашивает страховые компании синхронно (предполагаем, что API компаний партнеров изменить нельзя)
* Публикует обновления продуктов в Kafka (`insurance-products-updates`)

Сервис `core-app`:
* Подписывается на `insurance-products-updates` для получения актуальных данных
* Публикует события оформления страховок в `policy-creations`
* Больше не делает синхронные вызовы к `ins-product-aggregator`

Сервис `ins-comp-settlement`:
* Подписывается на `policy-creations` для получения данных о новых страховках
* Подписывается на `insurance-products-updates` для актуальных тарифов
* Исключает ежедневные синхронные вызовы к `core-app`

### 3. Использование Transactional Outbox
Применяем паттерн для `core-app` при оформлении новых страховок

Преимущества:
* Гарантированная доставка событий
* Согласованность данных между сервисами
* Отказоустойчивость при сбоях

## Ожидаемый эффект:
* Улучшение времени отклика сервиса `core-app`, так он избавиться от части синхронных вызовов
* Улучшение отказоустойчивости
* Возможность горизонтального масштабирования
* Соблюдение SLA для B2B-клиентов
* Подготовка к добавлению новых страховых компаний
